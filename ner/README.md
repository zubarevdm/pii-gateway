# NER для детекции персональных данных

Слой 2 шлюза сейчас работает на Natasha. Здесь собираем размеченный датасет,
меряем текущий детектор шлюза (regex + контрольные суммы + Natasha) и дообучаем
собственную модель, которая заменит Natasha, если окажется лучше.

**Статус:** тестовый набор готов, бейзлайн шлюза измерен. Следующий шаг — обучение модели.

## Тестовый набор

297 русских текстов шести жанров (тикеты поддержки, чаты, официальные документы,
банк/медицина/госуслуги, сложные негативы, длинные тексты с опечатками), 13 меток,
около 400 сущностей. 87 примеров не содержат персональных данных: на них видно
ложные срабатывания («вера в себя», «Лев Толстой», ОГРН, трек-номера).

Разметка сделана двумя независимыми разметчиками (Claude и GigaChat-2-Max) по
[правилам разметки](docs/annotation.md). Границы спанов у обоих приведены к правилам
одним и тем же кодом. Согласие разметчиков — **F1 0.91**, полностью совпали 248 примеров
из 297. 59 расхождений разрешены вручную вслепую: для каждого вопроса случайно
выбиралось, чей вариант показан как «A». После сверки часть решений уточнена
отдельными правками ([corrections.jsonl](data/test/corrections.jsonl)).

Тексты написаны LLM, а не собраны из реальной переписки: реальные персональные
данные в открытом репозитории выкладывать нельзя. Из шаблонов, по которым
генерируется обучающая выборка, тест не собирается, иначе метрика покажет заучивание шаблонов.

## Результаты

| Детектор | PII F1 strict | PII F1 overlap | Masking recall | Ложные срабатывания¹ | мс/текст |
|---|---|---|---|---|---|
| Шлюз: только regex | 0.33 [0.28–0.39] | 0.34 [0.29–0.39] | 0.22 [0.18–0.26] | 14 | <0.1 |
| Шлюз: regex + Natasha | 0.62 [0.57–0.66] | 0.74 [0.71–0.78] | 0.72 [0.68–0.77] | 45 | 2.4 |

В скобках 95% доверительный интервал (бутстрап по примерам).
**Strict** — совпадают метка и границы, **overlap** — метка совпадает, спаны пересекаются.
**Masking recall** — доля персональных данных, которые детектор хоть как-то закрыл,
независимо от метки. Для шлюза это главная цифра: сейчас **28% персональных данных уходят
наружу незамаскированными**. ORG_ID в сводные метрики не входит, NICK объединён с PER.
¹ Сущности, найденные в примерах, где персональных данных нет.

Где текущий детектор слаб (overlap recall):
- **NICK 0.00, BIRTHDATE 0.15** — ников и возраста нет в схеме шлюза, дата рождения ловится только в формате `дд.мм.гггг`;
- **CARD 0.33** — все полные номера найдены, но маскированные (`**** 1208`) не проходят проверку Луна и пропускаются;
- **PASSPORT 0.44, PHONE 0.70** — разорванные текстом номера, номера словами, нестандартные форматы;
- **ADDRESS precision 0.44** — Natasha размечает любой город, а по правилам город без улицы не адрес.

Подробности по меткам: [eval/baseline-gateway.json](eval/baseline-gateway.json).

## Воспроизведение

```bash
pip install -e ".[dev]"
python -m ru_pii_ner.evaluate gateway          # бейзлайн шлюза -> eval/baseline-gateway.json
python -m ru_pii_ner.generate -n 5000          # синтетическая обучающая выборка
python -m ru_pii_ner.adjudicate agreement      # согласие двух разметчиков теста
```

## Состав

- `src/ru_pii_ner/generate.py` — синтетическая обучающая выборка по шаблонам с корректными контрольными суммами.
- `src/ru_pii_ner/testset.py` — черновики теста с инлайн-разметкой, экспорт в Label Studio.
- `src/ru_pii_ner/llm_annotate.py` — вторая независимая разметка через GigaChat.
- `src/ru_pii_ner/adjudicate.py` — согласие разметчиков, вопросы по расхождениям, сборка `test.jsonl`.
- `src/ru_pii_ner/evaluate.py` — метрики, доверительные интервалы, файл бейзлайна.

## Ограничения

- Тест небольшой: по редким меткам (SNILS, ACCOUNT, DOC_ID) 4–10 примеров, интервалы широкие.
- GigaChat участвовал в разметке теста, поэтому для оценки LLM как детектора нужна модель другого семейства.
- NER размечает прямые идентификаторы. Риск деанонимизации по совокупности косвенных признаков
  («в 11 «А» три Саши») оценивается на уровне документа, и этот подход его не закрывает.
