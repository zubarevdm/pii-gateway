# PII-шлюз перед LLM

**Пользуйтесь ChatGPT, Claude и DeepSeek в работе — персональные данные не покидают ваш контур.**

Локальный OpenAI-совместимый прокси, который находит и обезличивает персональные
данные (152-ФЗ) в запросе **до** отправки в зарубежную модель, а в ответе
восстанавливает их обратно. Карта соответствия «плейсхолдер ↔ значение» хранится
только локально и **никогда не уходит в облако**.

> ⚠️ **Честное позиционирование.** Инструмент **радикально снижает риск** утечки
> ПД за рубеж, но не является автоматической гарантией полного соответствия
> 152-ФЗ и не заменяет юридическую экспертизу. См. [docs/legal/ОТКАЗ.md](docs/legal/ОТКАЗ.md).

## Как это работает

```
Сотрудник пишет запрос с ПД
        │
        ▼
┌─────────────────────────────────────────────┐
│  ЛОКАЛЬНЫЙ ШЛЮЗ (контур клиента)             │
│                                             │
│  1. Детекция ПД                             │
│     • Слой 1 — regex + контрольные суммы    │
│       (телефон, email, ИНН, СНИЛС, ОГРН,    │
│        паспорт, карта, счёт, госномер, IP)  │
│     • Слой 2 — RU NER (Natasha):            │
│       ФИО, организации, адреса              │
│                                             │
│  2. Токенизация → [PERSON_1], [PHONE_1]…    │
│     Карта маппинга в памяти (Vault),        │
│     НЕ покидает контур                      │
│                                             │
│  3. Аудит: факт+тип маскировки, без ПД      │
└───────────────────┬─────────────────────────┘
                    │  (уходит ТОЛЬКО обезличенный текст)
                    ▼
        Зарубежная модель (OpenAI / Anthropic / …)
                    │
                    ▼
┌─────────────────────────────────────────────┐
│  ЛОКАЛЬНЫЙ ШЛЮЗ                              │
│  4. Восстановление плейсхолдеров по Vault   │
└───────────────────┬─────────────────────────┘
                    ▼
        Сотрудник видит обычный ответ с данными
```

Ключевой принцип: **шлюз не видит и не хранит ПД дольше времени запроса.** Карта
маппинга живёт только в оперативной памяти процесса. Поэтому оператор шлюза не
становится новым «местом утечки» и не создаёт ещё одну базу ПД.

## Быстрый старт

```bash
# 1. Зависимости (Python 3.11+; проверено на 3.14)
pip install -r requirements.txt

# 2. Настройка
cp .env.example .env
#   укажите UPSTREAM_BASE_URL и, при желании, UPSTREAM_API_KEY

# 3. Запуск
uvicorn app.main:app --host 127.0.0.1 --port 8787
```

Теперь направьте любой OpenAI-совместимый клиент на `http://127.0.0.1:8787/v1`
вместо `https://api.openai.com/v1`. Всё остальное работает как обычно.

### Проверить обезличивание без модели

```bash
curl -X POST http://127.0.0.1:8787/anonymize \
  -H "Content-Type: application/json" \
  -d '{"text":"Клиент Петров, тел +7 900 123-45-67, ИНН 7707083893"}'
```

Ответ покажет обезличенный текст, обратное восстановление и статистику по типам.

## Что детектируется

**Слой 1 — структурированные ПД (regex + контрольная сумма, ≈100% точность):**
телефон, email, ИНН (с проверкой контрольного разряда), СНИЛС, ОГРН/ОГРНИП,
паспорт РФ, банковская карта (Луна), расчётный/лицевой счёт, госномер авто, IP,
дата рождения (по контексту).

**Слой 2 — свободный текст (контекстный NER, Natasha):** ФИО, организации,
адреса/населённые пункты.

Контрольные суммы — важная деталь качества: случайные 10 цифр не маскируются как
ИНН, а не-карта не маскируется как карта. Это отличает продукт от «regex-поделки».

## Архитектура кода

```
app/
  detectors/
    base.py             # Entity, протокол Detector, EntityType
    validators.py       # контрольные суммы ИНН/СНИЛС/ОГРН/Луна
    regex_detector.py   # слой 1
    natasha_detector.py # слой 2 (ленивая загрузка модели)
    pipeline.py         # слияние слоёв + разрешение пересечений
  anonymizer/
    vault.py            # локальная карта маппинга (НЕ уходит в облако)
    anonymizer.py       # обезличивание + восстановление
  audit/
    logger.py           # аудит без ПД (JSON Lines) — доказательство для РКН
  proxy/
    chat.py             # OpenAI-совместимый /v1/chat/completions
  config.py             # настройки из .env
  service.py            # сборка ядра (singleton)
  main.py               # FastAPI-приложение
tests/                  # 16 тестов: regex, round-trip, pipeline, HTTP
docs/                   # юридические шаблоны и продажные материалы
```

Слой детекции построен на едином интерфейсе `Detector`, поэтому позже легко
добавить третий слой (анти-реидентификация, локальная LLM-NER) без переписывания.

---

## Тесты

```bash
python -m pytest tests/ -q
```

Покрыто: контрольные суммы, отсутствие ложных срабатываний на обычном тексте,
обратимость round-trip, консистентность плейсхолдеров, приоритет структурного
слоя над NER при пересечении, и сквозной HTTP-тест (ПД не уходят в upstream и
восстанавливаются в ответе — на фейковом upstream без реального ключа).
